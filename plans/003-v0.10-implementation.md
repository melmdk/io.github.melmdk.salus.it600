# v0.10 Implementation Plan — pairing reuse, protocol detection, new devices

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Status:** Not started
**Created:** 2026-10-26

**Goal:** Ship v0.10.0 of the Salus IT600 Homey app. Pairing and repair reuse the app's existing gateway connection. The gateway protocol is auto-detected (CBC-256, CBC-128, CCM). Errors are ones a user can act on. It adds the SQ610 Away preset, signal diagnostics, thermostat problem alarms and a wiring-centre device.

**Architecture:**
- Encryption moves behind a `GatewayProtocol` interface. `IT600Gateway` takes an injectable transport, so detection and polling can be tested against a fake gateway built from sanitised real fixtures.
- The app owns the single gateway connection: host, EUID and detected protocol, persisted in the `gateway` setting.
- All drivers pair and repair through one shared helper.
- New parsing is ported from `salus-it600-client` 0.7.0 (MIT/Apache-2.0).

**Tech Stack:** TypeScript 5.9, Homey SDK 3 (`compatibility >=12.4.0`), Node `crypto` (`aes-256-cbc`, `aes-128-cbc`, `aes-256-ccm`), `node:test` + `node:assert/strict`.

**Spec:** `plans/002-v0.10-pairing-protocol-devices-design.md` (approved 2026-10-26). Read it before starting.

## Global Constraints

- **Branch:** `feat/v0.10`, created from `fix/poll-robustness` (commit `4e6e153`). Conventional Commits; scopes `api`, `thermostat`, `sensor`, `switch`, `cover`, `pairing`, `flow`, `ci`, `wiring-centre`.
- **No new runtime dependencies.** Dev-only tooling is fine.
- **Never break paired devices:** keep device IDs (`data.id` = `UniID`), keep all existing capabilities, add new ones with `addCapability` in `onInit`, and never remove one.
- **Polling always runs and reconnects on its own** (behaviour of `4e6e153`). Only one request in flight to the gateway (keep the `Mutex`).
- **Never log, commit or write into plans/docs** the real EUID, `NetworkSSID`, `NetworkPassword`, `LocalModeAccessCode`, or MAC/IP fields. The real EUID lives only in the git-ignored `test-config.json`. Tests use the dummy EUIDs `0123456789ABCDEF` (16 hex) and `0123456789AB` (12 hex).
- **Exact user-facing error texts:**
  - `Wrong EUID: check the 16 characters on the gateway label`
  - `No gateway answering at <ip>`
  - `Gateway firmware uses an encryption this app doesn't support`
- **EUID placeholder text:** `16 characters from the gateway label`
- **Protocol probe order:** `aes-256-cbc`, then `aes-128-cbc`, then `aes-256-ccm`. Persist the result; never probe once a stored protocol works.
- **Combined `deviceid` requests are OFF by default.** They are switched on only after the live check in Task 4 passes.
- **SQ610 preset reporting is unchanged apart from adding `Away` (HoldType 6).** `Temporary Hold` keeps its name and current behaviour.
- **Live gateway access** (approved): reads, fixture capture, wrong-key probes, and writes **only to thermostat "Gæsteværelse"**, restoring its original setpoint and preset afterwards.
- **Version `0.10.0`** in `.homeycompose/app.json`, `package.json` and `CHANGELOG.md`. No tag and no publish without the owner's go-ahead.

## Review Focus

1. **Gateway unreachable at app start** (after a power cut the server boots before the UDM). Polling must keep retrying and connect later. Pairing must show the credentials screen with `No gateway answering at <ip>`, not hang. → Task 3: test `connect reports unreachable`; Task 6: test `pairing shows credentials when gateway down`.
2. **A stored protocol that stops working** (gateway firmware update). Re-detect once, persist the new protocol, and don't loop. → Task 3: test `falls back to detection when stored protocol fails`.
3. **A device missing from one poll, or offline.** Mikkel was absent at pairing; "Multirum" has `OnlineStatus_i` 0. Pairing still offers missing devices. Paired devices go unavailable rather than disappearing. → Task 6: test `pairing list merges last-seen devices`; Task 5: test `offline thermostat parses as unavailable`.
4. **EUID typed in lowercase, with spaces, or as 12 hex characters.** Normalise before key derivation. CCM inserts `09 02` after byte 3 for 12-character EUIDs. CBC hashes the lowercase EUID. → Task 2: tests `normalises euid input` and `ccm 12-char euid vector`.
5. **Upgrade from v0.9.6.** Only the legacy `gateway` setting `{host, euid}` exists, with no protocol, and devices lack the new capabilities. The migration must keep working and add capabilities lazily. → Task 6: test `migrateGatewaySettings accepts legacy shapes`; Task 8 checks the capability migration.

  - Output goes to `test/fixtures/protocol-vectors.json`.
  - Also take **the real framing quirks** from the raw captures in `test/local/`:

- [ ] **Step 2: Write the failing tests** in `test/protocol.test.ts`:
  - `cbc256 matches reference vector` and `cbc128 matches reference vector`: `wrapRequest(plaintext)` equals the vector hex, and `unwrapResponse(vector)` equals the plaintext.
  - `cbc unwrap ignores non-block-aligned trailer` uses `cbcTrailerCase`.
  - `ccm 16-char euid vector` and `ccm 12-char euid vector`: with `nonceFn` returning the vector nonce, `wrapRequest` equals the wire hex. `unwrapResponse(wire)` equals the plaintext.
  - `ccm rejects tampered tag`: flipping one tag byte makes `unwrapResponse` throw.
  - `normalises euid input`: `normaliseEuid(' 0123 4567 89ab cdef ')` returns `'0123456789ABCDEF'`. An `AesCbcProtocol` built from lowercase input produces the same ciphertext as one built from uppercase (the key hashes `euid.toLowerCase()`).
  - `candidates are in probe order`: `protocolCandidates('0123456789ABCDEF').map(p => p.name)` deep-equals `['aes-256-cbc','aes-128-cbc','aes-256-ccm']`. For a non-hex EUID the list leaves CCM out.
- [ ] **Step 3:** Run `npm test`. Expected: FAIL.
- [ ] **Step 4: Implement `lib/protocol.ts`.**
  - **CBC:** fixed IV `ENCRYPTION_IV` from `lib/constants.ts`. The key is `md5('Salus-' + euid.toLowerCase())` (16 bytes) for CBC-128, or that plus 16 zero bytes for CBC-256. `unwrapResponse` truncates to a multiple of 16 before decrypting.
  - **CCM:** use `crypto.createCipheriv('aes-256-ccm', key, nonce, { authTagLength: 8 })`. The key is the EUID bytes (with `09 02` inserted at offset 3 for 6-byte EUIDs) followed by the ASCII bytes of `9a4ba190ac2b5139b32c3528`. The wire format is `ciphertext ‖ tag(8) ‖ nonce(8)`.
  - **Default `nonceFn`:** 3 random bytes, then the counter as 2-byte big-endian, then the low 3 bytes of `Math.floor(Date.now()/1000)` big-endian.
  - **File header:** an attribution comment naming `salus-it600-client` 0.7.0 (MIT/Apache-2.0).
